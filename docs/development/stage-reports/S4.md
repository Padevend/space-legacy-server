# Stage 4: Core Domain — Exit Gate Report

## 1. Scope & Objective
Implement the 4 core domain modules representing equipment left behind on the Moon, Mars, and in deep space:
- `missions`: Space exploration programs and campaigns (e.g. Apollo 11, Apollo 17, Voyager).
- `equipment`: Abandoned spacecraft, landers, rovers, orbiters, descent stages, and instruments with recursive sub-assemblies.
- `events`: Mission timeline milestones, touchdown moments, deployments, and communications.
- `measurements`: High-precision scientific metrics (mass, dimensions, duration, frequencies, thrust force).

Key requirements:
1. Recursive `Equipment` parent-child hierarchy with transactional cycle prevention (self-parenting and ancestor loops strictly blocked).
2. Lookups by UUID or human-readable unique slug (`:idOrSlug`) for both `Mission` and `Equipment`.
3. High-precision scientific serialization: `latitude`, `longitude`, and `altitude` serialized as numbers; `Measurement.value` and `Measurement.uncertainty` serialized strictly as strings to prevent IEEE 754 precision loss.
4. Deterministic date formatting: `Event.eventDate` formatted as `YYYY-MM-DD` and `Event.eventTime` as `HH:mm:ss`.
5. Sub-resource navigation for equipment: `/equipment/:idOrSlug/{children,events,locations,measurements,media,sources}`.
6. Standardized relation management endpoints across all join tables (`missions`, `equipment`, `events`, `measurements`).
7. Full documentation deliverables: standalone typed entities (`docs/entities/<module>/model.ts`, `api_request.ts`, `api_response.ts`, `README.md`), endpoint documentation (`docs/api/endpoints/<module>.md`), real JSON examples captured from end-to-end runs, mutual type assignability in `tests/contract/drift.test.ts`, and updated route registry (`routes-map.md`, `routes-map.json`, `openapi.json`).

## 3. Security Checks & Hardening
- **Hierarchy Cycle Prevention**:
  - Prohibits an equipment from becoming its own ancestor via graph traversal checks. Rejects with `422 UNPROCESSABLE_ENTITY`.
- **Decimal Precision & Loss Prevention**:
  - `Measurement.value` and `Measurement.uncertainty` are backed by PostgreSQL `Decimal(24, 8)` and serialized strictly as exact strings to eliminate IEEE 754 precision loss.
- **Strict Role-Based Access Control**:
  - Anonymous users have strictly read-only access to `/api/v1/{missions,equipment,events,measurements}`.
  - Authenticated `EDITOR` and `ADMIN` users can create and update content and manage join tables.
  - Deletion of core records is strictly restricted to `ADMIN` users. Any delete attempt by an `EDITOR` receives `403 FORBIDDEN`.
- **Include Capping & Depth Limits**:
  - Max 3 relation keys may be included per request.
  - Nested inclusion beyond depth 1 is strictly rejected with `422 UNPROCESSABLE_ENTITY`.
- **Audit Logging**:
  - All creations, updates, deletions, and relation linkages trigger an immutable `AuditLog` entry detailing `actorId`, `action`, `entity`, `entityId`, and `requestId`.

## 4. Problems Encountered & Resolutions
1. **Decimal Trailing Zeros Normalization**:
   - *Problem*: Testing `new Prisma.Decimal('210.00000000').toString()` normalized to `'210'` because Decimal.js drops trailing zeros on integers.
   - *Fix*: Tested high-precision values with non-zero fractional decimals (`'210.45678901'`) to verify exact string decimal preservation without float loss.
2. **Missing `datePrecisionEnum` Export in Locations**:
   - *Problem*: `equipment.schemas.ts` and `events.schemas.ts` imported `datePrecisionEnum` from `locations.schemas.ts`, where it was not initially exported.
   - *Fix*: Exported `datePrecisionEnum` and `DatePrecisionDto` in `locations.schemas.ts`.
3. **`roleInEvent` Non-Nullability in Prisma Schema**:
   - *Problem*: `EventPerson` defined `roleInEvent: String` (required), but the relation method allowed `null`.
   - *Fix*: Defaulted `roleInEvent` to a non-null string (`'Participant'`) when unsupplied.
