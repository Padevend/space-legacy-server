# Stage 3: Reference Data — Exit Gate Report

## 1. Scope & Objective
Implement the 4 core reference data modules required by the SPACE LEGACY system:
- `celestial-bodies`: Solar system bodies (Moon, Mars, asteroids, lagrange points, deep space).
- `locations`: Named coordinates on celestial bodies, coordinate reference systems, landing sites, impact sites, orbital zones.
- `people`: Astronauts, mission commanders, engineers, historical figures with affiliations.
- `sources`: Primary sources (NASA history, Apollo Lunar Surface Journal, NSSDCA catalog, technical reports) providing traceability.

Key requirements:
1. Public anonymous read-only endpoints under `/api/v1/...` with pagination, search, filters, and HTTP caching (ETags, `If-None-Match` -> 304 Not Modified).
2. Admin/Editor secured endpoints under `/api/v1/admin/...` for creation and updates; Admin-only restriction for deletion.
3. Coordinate validation: latitude [-90, +90], longitude [-180, +180].
4. Serializer precision: decimal coordinates serialized as numbers (not strings); ISO 8601 UTC date formats.
5. Audit trail: modifications logged in `AuditLog`.
6. Full documentation deliverables: standalone typed entities (`docs/entities/<module>/model.ts`, `api_request.ts`, `api_response.ts`, `README.md`), endpoint markdown docs (`docs/api/endpoints/<module>.md`), real JSON examples captured from end-to-end runs, mutual type assignability in `tests/contract/drift.test.ts`, and updated route registry (`routes-map.md`, `routes-map.json`, `openapi.json`).

## 3. Security Checks & Hardening
- **Strict Role-Based Access Control**:
  - Anonymous users have strictly read-only access to `/api/v1/{celestial-bodies,locations,people,sources}`.
  - Authenticated `EDITOR` and `ADMIN` users can create and update reference data.
  - Deletion of reference records is strictly restricted to `ADMIN` users. Any delete attempt by an `EDITOR` receives `403 FORBIDDEN`.
- **Coordinate Boundary Validation**:
  - Zod schemas enforce real physical limits: `latitude >= -90 && <= 90`, `longitude >= -180 && <= 180`.
- **URL Sanitization & Format Checks**:
  - Source URLs are validated against valid RFC 3986 format to prevent protocol injection.
- **Audit Logging**:
  - All creations, updates, and deletions trigger an immutable `AuditLog` entry detailing `actorId`, `action`, `entity`, `entityId`, and `requestId`.

## 4. Problems Encountered & Resolutions
1. **Prisma Type Import Issue in `LocationsRepository`**:
   - *Problem*: `import type { Prisma } from '@prisma/client'` stripped the `Prisma` symbol at runtime, causing `ReferenceError: Prisma is not defined` when calling `new Prisma.Decimal()`.
   - *Fix*: Changed import to `import { Prisma, type Location, type LocationType } from '@prisma/client'`.
2. **Hono OpenAPI Delete Middleware Binding Issue**:
   - *Problem*: Passing `requireRole('ADMIN')` as a middleware argument inside `adminRouter.openapi(deleteRoute, requireRole('ADMIN'), handler)` broke Hono OpenAPI's signature expectation, causing an uncaught exception (`500 INTERNAL_ERROR`).
   - *Fix*: Bound `adminRouter.openapi(deleteRoute, controller.delete)` directly, and enforced the `ADMIN` role check explicitly within `controller.delete` (throwing `AppException.forbidden('Admin role required to delete...')`).
